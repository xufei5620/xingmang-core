# ADR-004：Connector 隔离第三方差异

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-08-26 |
| 来源 | 规格 v2.1 §3 ADR-004（本文件拆分后为唯一权威版本） |

## 背景

平台管理多个不受控演进的第三方系统，需要把版本差异、字段差异与故障面
限制在明确边界内。

## 决策

每类被管理系统使用独立、版本化 Connector。Connector 必须提供：

- 连接配置 Schema；CredentialRef；目标地址 allowlist；版本探测和版本指纹；
  Capability 声明；健康检查；超时、重试、退避和限流；错误映射；数据新鲜度；
  幂等和写后读取；Kill Switch；契约测试；兼容矩阵；运行指标和审计摘要。

## 理由

差异必须隔离在 Connector 内，领域层与页面不感知供应商细节。

## 边界与后果

### 读通道优先级

```text
稳定官方只读 API
> 受控只读 Projection / 只读副本
> 独立采集 Sidecar
> 临时浏览器自动化
```

### 写通道优先级

```text
官方 Admin API
> 严格限定能力的 Management Sidecar
> 受控数据库函数（仅极少数例外）
> 浏览器自动化（临时，不得长期依赖）
```

### 铁律

- 平台永不直接更新 NewAPI、Sub2API 原始业务表；
- 页面和工作流不得直接调用第三方 Admin API；
- 第三方错误不得原样透传给用户；
- 第三方升级前必须运行 Connector 契约和兼容性门禁。

## 替代方案

领域层直接调用第三方 API：因耦合与不可测试否决。

## 重评条件

无。

## 相关契约

`contracts/connectors/`（Connector Manifest，示例见规格附录 C）。
