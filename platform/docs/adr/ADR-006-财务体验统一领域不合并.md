# ADR-006：财务体验统一，支付、对账和开票领域不合并

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-08-26 |
| 来源 | 规格 v2.1 §3 ADR-006（本文件拆分后为唯一权威版本） |

## 背景

财务信息分散在支付、对账、开票多个来源系统，需要统一管理体验，
但各领域安全边界与真相源不同。

## 决策

后台产品体验统一为"财务中心"，但底层保持三个领域：

```text
Payment
Reconciliation
Invoice
```

统一财务语义：

```text
cash_paid
bonus_granted
cash_consumed
bonus_consumed
cash_refunded
invoice_eligible
invoice_allocated
```

## 理由

统一体验降低操作成本；领域独立保住安全边界与真相源。

## 边界与后果

### 核心规则

> 只有实际真实充值且已经消费的现金金额可开票；赠送、返利、兑换码、
> 管理员赠额和其他非现金额度不可开票。

- 开票资格算法只在开票系统实现；
- 平台不得复制资格算法；
- 平台可聚合、展示和发起受控管理 Action；
- 原始支付订单仍以来源系统为真相源；
- 不同来源系统的财务隔离不能被统一看板破坏。

## 替代方案

合并财务数据库：因真相源与隔离破坏否决。

## 重评条件

无。
