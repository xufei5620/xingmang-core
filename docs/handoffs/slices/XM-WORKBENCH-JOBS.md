# XM-WORKBENCH-JOBS：工作台的「失败任务」接上真实数据

- **status:** implemented，未上线。**纯前端**：不改后端、不改契约、不动数据库。
- **branch:** `ai/claude/XM-WORKBENCH-JOBS`（自 `release/v0.1-launch`）。

## 为什么

运营工作台「我的待处理」的「失败任务」一类写着：

> 后台任务页与 River 查询端点尚未建

**这句话在 XM-JOBS0 交付那天就过期了。** `/api/v1/jobs/runs` 一直都在（router.go
里 `ops.read` 那一组），后台任务页 `/jobs` 也一直都在，前端连
`api/jobs.ts` 客户端都写好了。于是**一个已经放弃重试的后台任务，在运营每天
第一眼看的那一屏上完全不可见**——它只存在于一个要主动点进去的页面里。

这是本轮第三次遇到同一类问题（前两次：凭据页的探测两格、连接器兼容矩阵）。
**占位比缺功能更糟**：缺功能是人知道要去别处找，占位是人以为这件事没做。

## 只收「已放弃」，不收「重试中」

`/jobs/runs` 能按 state 筛，`retryable`（这次失败了、还会再试）也拿得到。
**刻意不列进来**：

「我的待处理」的口径是"我必须动手的事"。一个 retryable 的任务不需要任何人动手
——它会自己再试，试成了就消失，试到用尽变成 `discarded` 自然出现在这里。把它
也列进来会让这张清单抖动：条目跳出来，几分钟后自己没了。**一张会抖的待办清单，
人很快就不看了**，那比少一类信息糟得多。

重试中的任务在后台任务页的「失败与重试」页签，那里才是看过程的地方；界面上
这句话也写出来了，不是默默省略。

`cancelled` 同样不收：那是有人主动取消的，不是失败。

## 改了什么

- `lib/workbench.ts`：`jobs` 分类从 `blockedBy` 改成 `source`；新增
  `workItemsFromJobRuns`。时刻优先 `finalized_at`（River 定终态的时刻），缺了
  退回 `attempted_at`，再退回 `created_at`——不显示"0 秒前"这种编出来的新鲜。
  链接直接落到 `/jobs?sub=repeated`（`state=discarded` 那个页签），点进去还要
  自己找是多余的一步。
- `pages/OverviewPage.tsx`：第六条 query（`state=discarded`，最多 20 条，
  `retry: false`）。**单独发**：它读不到时只有「失败任务」这一类降级，告警照常
  显示——合成一个 error 会让缺 `ops.read` 时整块变红。`WorkList` 里
  `jobsOnly` 时用 jobs 的加载/错误态，其余时候用告警的。
- 三处文案跟着改：分类说明（现在两类有源，并说明为什么不含重试中）、
  「全部」空态（不再把"失败任务还没接入"写进去，因为它接入了）、
  「失败任务」空态单独一句。

## 测试

- `lib/workbench.test.ts`：分类有源的从 `["incidents"]` 变成
  `["incidents","jobs"]`（这条断言**故意**要求每接一类源就改一次）；新增五条
  ——重试中/已取消不进待办、完成与运行中同样不进、标题与色调与目标页签、
  三级时刻回退（夹具让三级各给不同数字，谁都替代不了谁）、未知 kind 显示原始值。
- `router.test.tsx`：新增两条——放一条 discarded 记录时工作台显示它且
  `href` 是 `/jobs?sub=repeated`；没有已放弃任务时说清"重试中的不计入"，
  而不是显示成「还没接」。

**做过变异验证**：把分类改回 `blockedBy`（原来那句过期的话），三条测试
（一条 lib、两条 router）如期变红。这些断言不是恒真的。

门禁：`pnpm -r typecheck` / `test`（1544 条全绿）/ `build`、
`scripts/check-governance.sh` 退出 0、`gitleaks protect --staged` 无泄漏。
后端未触及。

## follow_ups

- 每类最多 20 条，取满时界面上**没有**说"被截断了"。告警那边有同样的问题
  （`RECENT_ALERTS_LIMIT` 有一句提示，这里没有）。真出现 20 条已放弃的任务时
  系统已经病得很重，但"看到的不是全部"仍然该说出来。
- 剩下四类（待审批 / 财务异常 / 即将到期 / 待评审变更）的 `blockedBy` 都还没
  复核过。按这一轮的经验，**它们也可能已经过期**——下一片值得逐条对着代码查一遍，
  而不是相信注释。
- 词汇有两套：这里的徽章是「已放弃」，后台任务页的页签叫「多次失败任务」。
  链接把两者连起来了，但同一个东西两个名字，长期该统一。
