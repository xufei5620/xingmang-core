# XM-CREDS-TAB-REFS：「连接与凭据」页签接上真实的凭据引用

status: implemented（本地门禁见下）
branch: ai/claude/XM-CREDS-TAB-REFS（自 release/v0.1-launch@8ca2910）
依据：2026-09-06 Sub2API 缺口普查「连接与凭据」区，两条 `[missing]`：
卡片「凭据引用：引用名 / 状态（已配置·未配置）/ 轮换周期 / 最近轮换 / 最后使用」，
以及统计卡「CredentialRef 状态」。

## 为什么这一片值得先做

产品负责人 2026-09-06 早上问的正是这件事：「这三个是填什么的」——他在全局的
「凭据」页看到三条缺失，但**平台页签上看不到自己这个平台缺哪条**。数据一直都在
（`GET /api/v1/credentials/expected` 与 `GET /api/v1/credentials`，全局凭据页已在
用），只是这一页把它写成了「未接入」。

## 做了什么

1. **「凭据引用」从占位卡片变成真表**。列：引用名 / 用途 / 状态（已配置·未配置）/
   指纹 / 版本 / 最近更新。只列 `platform` 等于当前页签的那几条——清单由后端给，
   前端不硬编码：硬编码的清单会在后端多一条或改名时继续显示「全部已配置」，而那
   正是上线前最不能说谎的一屏。
2. **统计卡「CredentialRef 状态」**从固定的「未接入」变成 `已配置 / 需要的总数`，
   有缺时挂一个「有未配置」的徽标。
3. **两条 Query 分开发**，不合成一条：清单不需要权限，元数据要
   `credential.manage`。只读操作员因此仍看得到「这条配了没有」，只是看不到指纹与
   版本，而不是整块变成「无权访问」；缺权限时表下方一行说明写清缺哪个权限。

## 明确不做

- **轮换周期（原型「90 天」）与「最后使用 / 最近验证」不列**：上游没有这两项数据。
  宁可少一列，也不拿「最近更新」冒充「最近轮换」或「最后使用」（宪法 12 条）。
  「最近更新」这一列的表头提示逐字写明：保存与轮换都会动它，它不是「最后使用」。
- **不显示凭据正文**，也不显示完整指纹（只前八位，够核对两处填的是不是同一个）。
- **健康探测历史卡片保持「未接入」**：独立探测历史确实还没有 Query，服务的
  `observed_at` 只是最近一次观测，不能证明凭据当前可用。
- 不加任何后端、不加任何新读取面。
