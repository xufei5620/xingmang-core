# XM-ALERTS-TAB-DURATION：告警页签补上「持续多久」「最近多久」和一个能分享的链接

status: implemented（本地门禁见下）
branch: ai/claude/XM-ALERTS-TAB-DURATION（自 release/v0.1-launch@8ca2910）
依据：2026-09-06 Sub2API 缺口普查「告警」区的四条 `[missing]`
（告警号、持续、时间范围筛选、筛选/排序进 Router Search Params）与两条 `[partial]`
（跳全局告警中心的可点链接、页头逐字）。

## 做了什么

1. **「持续」列**。首次发现到恢复；未恢复的算到取数那一刻。这一列的用处是一眼分出
   「刚抖了一下」和「已经烧了一小时」——原型点名要它，而在这之前页面只给两个时间戳，
   要人自己心算。取整到分钟且**不四舍五入**（把 1 小时 59 分说成 2 小时会让人以为自己
   晚了一分钟）。可排序：未恢复的按「到此刻」算，于是同样时长里还在烧的排在前面。
2. **「时间」范围收窄**（最近 24 小时 / 7 天 / 30 天 / 不限），进 URL（`?alert_window=`），
   默认不限。按 **`last_seen_at`** 而不是 `opened_at` 过滤：一条两个月前开、五分钟前
   还在响的告警，在「最近 24 小时」里必须看得见——它正是此刻要处理的那条；按开始时间
   过滤会把最该看的长期故障藏起来。旁边一行说清这是**对已取回那一批的收窄**，不是查询
   条件，并显示当前隐藏了几条（宪法 12 条：不能让人以为更早的记录消失了）。
3. **筛选 / 排序 / 列可见性 / 密度进 URL**，并接上服务端个人视图：表格从 `DataTableV2`
   换成仓库既有的 `PersistentDataTable`，新增两个表键 `platform.sub2api.alerts` /
   `platform.newapi.alerts`。后端对表键只做**格式**校验（`savedviews.ValidateTableKey`
   是一个正则，不是白名单），所以这是纯前端改动，没有新后端、没有新审批。
4. **「编号」列**：告警 ID 的前八位（大写、等宽），完整 ID 在 `title` 里可复制。
   见下面「明确不做」。
5. **页头改为逐字「Sub2API · 告警」**（冻结 IA 第 7 格），底部那句「前往全局告警中心」
   变成真的可点链接 `/alerts`。

## 明确不做

- **不编造 `AL-2608-0119` 那种带序号的告警号**。后端没有这个字段，序号也不能由前端生成
  ——两个人打开同一页会看到不同的序号，而编号的全部价值就是「我们说的是同一条」。
  显示真实 ID 的前八位是诚实的替代；带序号的可读编号需要后端加一列，已登记为待办。
- **「对象」列不做**：原型要「出问题的渠道/账号/连接」，而结构化的对象字段不存在，
  只有 `detail` 里的自由文本。从自由文本里抠对象名会在措辞一变时静默错位。同样登记为
  需要后端字段。
- **平台页仍然没有确认/静默/批量操作**：处置在全局告警中心由 Action 与权限边界执行并
  保留审计。这一片只让「看」更有用。
