## scope / summary

本片只实现 R214-1 的本地、纯数据契约：

- `PluginAdmission` 严格版本化加载器：exact tag/artifact/size/SHA、source commit、
  provenance/SBOM/license、CPA build/OS/arch/variant/ABI、capability allow/deny、路由与
  config digest；拒绝 latest/range/prerelease/manual-unverified/auto-update、unknown 或
  duplicate 字段/ID/capability、大小/大小写/URL 漂移、unsigned opaque native binary。
- `PluginStoreSource` 严格来源元数据：HTTPS、精确 host/repository allowlist、registry
  hash/signature、有限大小、CredentialRef 形态和禁止 fallback；description/readme 只作为
  不可信显示文本。
- 四源 inventory join：物理 discovery 文件（按 variant/platform/root 优先级）、config、
  runtime、store-source/admission；输出仅 path class + digest，发现 shadow、hash/size/
  config/version/author/repository/capability/route drift、隐式 enabled、global disabled
  effective、孤立/未知行、重启需求与 coverage 不完整。
- `cmd/cpa-plugin-assess`：仅读取显式本地 policy/source/evidence JSON，输出稳定 findings
  与 `approved:false` 的 unsigned candidate；plugin-free 空 policy 只有在完整四源证据、
  global disabled 且无任何插件行时才 PASS。

无网络、下载、安装、加载、执行、启停、删除、配置、OAuth、重启、CPA/SSH、凭据解析、
数据库、迁移、Compose 或运行时 UI 接线。

## decisions

1. policy JSON 必须显式 `deny_by_default:true` 与 `admissions:[]`；省略或 false 均拒绝。
   空 admissions 是唯一合法的 plugin-free baseline，不能用 fake/sample admission 代替。
2. native 插件的 `unsandboxed_residual_risk` 是派生事实；任何 wire 字段（含 Unicode 转义
   形式）均拒绝，且该显示位不进入 policy canonical digest；返回候选始终 `approved:false`。
3. policy/source/admission 列表在 canonical digest 前按稳定 ID 与 capability 顺序排序；
   duplicate、case collision、same-priority shadow 都 fail closed。
4. inventory 物理优先级固定为 variant > platform > root；同优先级以 digest/size 稳定排序
   选出展示行，同时保留 `shadow_conflict` error。store source 为空时，非空 admission
   policy 的 coverage 不完整；assessment 直接拒绝缺失的 source projection。
5. runtime `Version`（或显式 `PluginVersion`）与 admission `ExactTag` 比对；CPA build
   版本不会被误当成插件版本。观察到的 capabilities 必须等于声明集合且属于 explicit
   allowed 集合；author/repository 有 pin 时逐项比对。
6. CLI 只接受 regular local files，拒绝 URL、UNC、NUL、`..` traversal、symlink；`--out`
   使用 `O_EXCL`，不覆盖既有证据。外部源失败绝不 fallback。
