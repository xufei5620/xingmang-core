## 0. 一页结论

- **支付**:原型已把独立平台「支付」整体删除,降为每个平台的「支付与财务」页签,
  跨平台汇总留在治理段「跨平台财务」。与指令 ✅ 完全一致,可直接执行。
- **开票**:原型把开票并入 Sub2API「支付与财务」的「开票」子页签(含开票详情页),
  治理段另有「开票集成」。方向 ✅ 一致;但 NewAPI 的财务页原型只画了 2 个子页签、
  **没有开票**,需产品负责人确认是否补齐。
- **模型保障**:原型明确写了「按你的意见从独立平台降为各 API 平台下的功能」,
  ✅ 支持降级;但最终态**把「渠道保障」页签从 Sub2API/NewAPI 里删掉了**
  (被「上游管理」顶替),页面 `#/s2/model` 变成导航进不去的孤儿路由。
  **指令与原型字面在这一点上冲突,已列三个选项待拍板,未硬编。**
- 现状与原型的结构性差距:平台目录多了 3 个不该存在的平台条目、
  导航少 1 个分组、全局段少 2 页、治理段少 3 页、平台页签集合全部要换、
  几乎所有页缺子页签、缺 404 兜底。

## 5. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 平台目录裁剪影响 Registry 动态平台 | `groupPlatforms()` 会把 Registry 里出现但目录没有的 `service_type` 自动补进导航。若生产 Registry 已登记 `payment`/`invoice`,裁剪后它们会以**原始 key** 重新出现在平台段 | 第 1 片需加显式排除名单,并在 Registry 侧确认这三个 service_type 的登记状态 |
| 旧书签失效 | 三个平台路径 + 三个 tab 值都在改 | 第 1 片的 redirect 全表 + 测试断言 |
| 与并行任务冲突 | XM-0037(成本线)、XM-0039、XM-0040 在同期分支上 | 第 1 片只碰导航/路由/平台目录,不碰面板组件;合并顺序由人类协调 |
| 「严格对齐」与指令的字面冲突 | §3 #1 模型保障 | 已列选项,**未硬编**,等拍板 |
| 原型自身的内部不一致 | 孤儿路由 `#/s2/model`;`s2/finance` 详情面包屑仍写旧名「财务中心」;NewAPI 财务页比 Sub2API 薄 | 已在 ADMIN-IA v3 §6 如实记录,不擅自「修好」原型 |

## 6. 本次审计的方法与可复现性

原型的最终态不是 `source/xingmangprototypev3.3.html` 本身:
`serve_xingmang_v4.py` 会对它做几十处字符串补丁(删除支付平台、重命名页签、
扩充服务器页签等)。**只读基线源会得到过时的 IA**(例如仍有「支付」平台、
仍叫「财务中心」「模型保障」)。

本审计的做法:把 `serve_xingmang_v4.py` 复制到临时目录,把 `SOURCE` 常量指向快照内的
`source/xingmangprototypev3.3.html`,只执行 `build_page()` 取渲染结果,
再从渲染结果里提取 `GLOBAL` / `PLATFORMS` / `GOV` / `EXT_UI` 四个数组、
全部 `subTabs(...)` 调用、全部 `phead(...)` 标题与 `route()` 分支。
**快照目录全程只读,未做任何修改。**

复现要点:`V[...]` 有重复赋值(如 `V["g/overview"]` 在 517 行与 1276 行各一次),
JS 后者覆盖前者,取值必须取**最后一次**赋值;早期定义是旧版遗留(旧名「运营总览」
「告警中心」「注册表」等),照抄会得到错误结论。
