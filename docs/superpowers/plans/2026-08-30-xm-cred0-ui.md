# XM-CRED0 Credential Management UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a settings-scoped credential management UI that lists only safe CredentialRef metadata and sends approved credential Actions without ever reading a secret back.

**Architecture:** `admin-web` owns the Query/Action transport wrapper and page state. A focused presentation component renders the metadata table and an inline paste-to-save form; its callbacks return only `action_run_id`. The backend endpoint, file SecretProvider, connector wiring, and approval center remain explicit not-connected seams.

**Tech Stack:** React 19, React Router, TanStack Query, Vitest + Testing Library, `@xingmang/ui-admin`, `@xingmang/ui-primitives`, Tailwind design tokens.

**Spec:** `docs/handoffs/ACCEPTANCE-LOG.md` (`PRIORITY 新增车道 F`) and `docs/handoffs/CODEX-SPRINT-2026-08-29.md` §7.6.

## Global Constraints

- Query reads use `GET /api/v1/credentials`; writes use `executeAction` only.
- Canonical Action IDs follow the existing three-segment kernel rule: `credential.secret.upsert@1`, `credential.secret.rotate@1`, and `credential.secret.revoke@1`; the UI copy may use the product short names `credential.upsert`, `credential.rotate`, and `credential.revoke`.
- Upsert/rotate params contain `credential_ref` and transient `secret_value`; revoke contains `credential_ref` and `reason`.
- The UI displays only CredentialRef, scope, updated-at, and an eight-character fingerprint prefix; secret values never appear in DOM, response projections, or error copy.
- `credential.manage` is a development-only default scope hint, not server authorization.
- No KMS/vault, approval center, connector wiring, migrations, or production deployment in this slice.
