# ADR-005：用户、员工和机器身份分域

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-08-26 |
| 来源 | 规格 v2.1 §3 ADR-005（本文件拆分后为唯一权威版本） |

## 背景

管理员和普通用户共享身份池会扩大权限误配和认证策略变更的影响范围。
机器使用人类账户会导致权限、审计和轮换不可控。

## 决策

使用同一 Keycloak 实例、两个 Realm：

- `solov`：终端用户 Realm，现有配置冻结；
- `solov-staff`：员工 Realm，关闭公开注册，强制 MFA/Step-up。

统一 Principal 类型：

```text
HumanPrincipal
ServicePrincipal
AIPrincipal
ServerAgentPrincipal
```

## 理由

见背景。

## 边界与后果

### ServicePrincipal

由 `solov-staff` Realm 的 Confidential Client / Client Credentials 签发，
用于：开票只读集成、内部程序、少量合作方、平台间 API。

验证项：`issuer / audience / client_id / scope / environment / expiration`。

### AIPrincipal

由平台 Agent Registry 登记，可底层映射到 ServicePrincipal，但必须附加：
`agent_id / agent_role / tool_policy_id / budget_policy_id / run_id`。
AI 不复用员工账号，不拥有通用管理员 Cookie。

### ServerAgentPrincipal

不建立成人类式 Keycloak 用户。采用：

```text
Tailscale Device Identity
+ 每 Agent 独立非对称密钥对
+ 平台登记 Agent ID
+ 命令信封签名
```

支持 Agent 密钥轮换、吊销和设备隔离。

## 替代方案

单 Realm + 角色区分：因影响范围与冻结需求否决。

## 重评条件

无。

## 相关契约

Keycloak 变更走 `docs/change-requests/`（见 ADR-016）。

## 证据编号

V8（Keycloak Identity Brokering，官方 Server Administration Guide）。
