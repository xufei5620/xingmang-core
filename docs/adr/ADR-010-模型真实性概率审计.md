# ADR-010：模型真实性采用概率审计；运营健康与身份一致性分开展示

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-08-26 |
| 来源 | 规格 v2.1 §3 ADR-010（本文件拆分后为唯一权威版本） |

## 背景

纯黑盒条件下无法绝对证明上游模型身份；把健康问题与身份问题混在一起
会产生误导性结论。

## 决策

Model Assurance 维护两条独立状态线：

### 运营健康

回答：接口是否可用；延迟和吞吐是否异常；流式是否正常；Tool Calling、
JSON Schema、上下文长度是否可用；错误率是否升高。

### 模型身份一致性

回答：输出分布是否与可信参考分布一致；是否出现长期漂移；是否出现能力
边界异常；是否需要人工复核。

## 理由

两类问题证据类型与处置动作不同，必须分开。

## 边界与后果

### 结论等级

```text
一致
大概率一致
不确定
可疑
高置信度不一致
```

禁止使用"100% 真模型""100% 假模型"。

### 探针纪律

- 只使用合成探针，不使用用户请求内容；
- 按流量、风险、上次验证时间和历史异常加权抽样；
- 参考端点和参考模型必须版本化；
- 上游返回的 `model` 字段不能单独作为身份依据；
- Tool Calling 可用性主要是能力证据，不是强身份凭证；
- MMD 只用于存在可比较参考分布的模型。

## 替代方案

固定提示题断言真假：因不可靠且可被规避否决（见规格 §1.4 非目标）。

## 重评条件

无。
