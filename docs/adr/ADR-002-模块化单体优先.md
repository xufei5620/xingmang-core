# ADR-002：模块化单体优先

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-08-26 |
| 来源 | 规格 v2.1 §3 ADR-002（本文件拆分后为唯一权威版本） |

## 背景

单人产品负责人加多 AI 团队，首要问题是规则统一、类型共享、测试完整和发布可控，
而不是服务数量。提前微服务化会增加网络、部署、版本、可观测性和跨服务调试成本。

## 决策

平台核心采用模块化单体：一个主要 Go 代码库、一个管理端应用、一套平台
PostgreSQL，通过编译期模块和明确接口分域。不提前采用微服务、微前端或运行时
任意插件。

## 理由

见背景。

## 边界与后果

- 模块只能调用其他模块公开接口、Query、Action 或事件；
- 禁止跨模块直接访问他人数据库表；
- 模块拥有自己的迁移、权限、Action、任务、告警和测试；
- 外部系统 Connector 可以独立包，但初期与 Platform API/Worker 同仓库发布；
- 某模块满足独立扩缩容、独立发布或独立故障域需求后，再单独 ADR 拆分。

## 替代方案

微服务/微前端起步：因团队形态与调试成本否决。

## 重评条件

某模块出现独立扩缩容、独立发布或独立故障域需求。

## 相关契约

`contracts/modules/`（模块 Manifest）。

## 证据编号

无。
