# CR-0003:开票系统用户按平台隔离(2026-08-28,产品负责人提出)

> 影响方:开票系统(Codex 线,K:/发票)为主;平台侧契约(XM-0028)为辅。
> 状态:**已批准的产品需求**,待开票线实施;与 CR-0002(口径冻结)并行不阻塞。

## 需求(产品负责人原话口径)

开票系统现页面**未区分用户来自 Sub2API 还是 NewAPI**,绑定账号处两个平台都
显示。要求改为**平台隔离**:

1. 用户身份按平台独立——**不存在一个用户同时在两个平台有账号**的模型;
   Sub2API 用户与 NewAPI 用户是两个独立的用户集合,即使邮箱相同也不合并;
2. 绑定账号页面:用户来自哪个平台,就**只显示该平台**的绑定入口与账号信息,
   另一平台不出现(不是置灰,是不渲染);
3. 开票申请、资格、历史等一切用户可见数据同样按平台隔离——Sub2API 用户
   永远看不到任何 NewAPI 字样与数据,反之亦然;
4. 依据:UI 原型确立的「按平台合入」原则(平台优先 IA)延伸到用户侧。

## 实施要点(开票线)

- 数据模型:用户/绑定记录挂 `platform` 标识(sub2api|newapi),入口即定平台,
  全链路查询带平台过滤;存量数据若有未标平台的,迁移时按绑定来源回填,
  回填不了的标 unknown 并在后台单列(不猜);
- 前端:入口/会话确定平台上下文,绑定页/申请页/记录页全部按上下文渲染,
  无跨平台切换控件;
- 员工后台(平台侧)不受限:运营在星芒平台的开票页签可以看全部平台
  (那是员工视角,与用户视角分域——见第二轮需求 R2 报告的分域纪律)。

## 平台侧配套(如需)

XM-0028 契约(contracts/ 开票部分)的用户/申请对象补 `platform` 字段;
星芒开票页签展示时按平台过滤的能力已具备(页签本身就在平台上下文里)。

## 验收

- 以 Sub2API 用户身份走完整绑定→申请流程,页面全程零 NewAPI 元素;反向同理;
- 同邮箱在两平台各自注册,数据互不可见、互不影响;
- 平台侧员工视角仍可跨平台查看(权限分域测试)。
