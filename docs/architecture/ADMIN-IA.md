# 管理后台完整信息架构(ADMIN-IA)v2 —— 平台优先

- 依据:规格 v2.1-RC2 全文;v2 按产品负责人意见改为**平台优先的三段式**:
  运营心智是「看某个被管系统怎么样」,导航跟着 Registry 的被管系统对象走。
- 状态:✅ 已上线 | 🔨 在建 | ⬜ 未建(标注里程碑)
- 本文件是导航与页面职责的单一清单:新增页面先改这里再动代码。

## 一、三段式总树

### 【全局】跨平台横切(少而稳)

| 页 | 状态 | 职责 |
|---|---|---|
| 运营总览 | ✅(重构中) | 全平台汇总:收入/成本/余额/告警摘要/新鲜度;每张卡可点入对应平台 |
| 告警中心 | 🔨 XM-0033 | 五态生命周期、去重、静默、Telegram/Webhook;可按平台过滤 |
| 审计事件 | ✅ | 全平台操作哈希链;可按平台/资源过滤(过滤为后续增强) |

### 【被管平台】主体,Registry 数据驱动(登记即出现,未接入显示占位)

**统一页签模板(命名与定位全平台一致——这是「统一命名」的落点):**

| 页签 | 定位 | 内容契约 |
|---|---|---|
| 概览 | 永远第 1 格 | 本平台关键指标卡+新鲜度+活动告警数 |
| 指标趋势 | 第 2 格 | 本平台全部 metric 的历史曲线 |
| 渠道/资源 | 第 3 格 | 平台的资源清单(渠道/账号/模型…按平台语义) |
| 连接与凭据 | 第 4 格 | Connection 状态、CredentialRef(永不显示明文)、Kill Switch |
| 告警 | 第 5 格 | 全局告警中心按本平台过滤的视图 |
| 操作 | 最后一格 | 本平台可用 Action 清单;L2+ 显示「需审批(F-B)」 |

**平台清单与状态:**

| 平台 | 状态 | 模板/变体 | 备注 |
|---|---|---|---|
| Sub2API | ✅ 概览+渠道已有(重构归位) | 标准模板 | 真实数据待只读凭据(XM-0017 已就绪) |
| NewAPI | ⬜ M1 | 标准模板 | 未接入前显示「未接入」占位(§12 惯例) |
| CPA | ⬜ M4 | 标准模板 | 同上 |
| 开票系统 | 🟡 契约草案(XM-0028) | 概览/申请/资格/文件 | 页面待 CR-0002 冻结+XM-0029;文件所有权在开票系统 |
| 支付 | ⬜ M3 | 概览/订单/通道/对账 | 退款等写操作需 F-B |
| 服务器 | ⬜ M2 | 概览/容器/证书/日志 | Server Agent(ADR-015) |
| 模型保障 | ⬜ M1.5 | 声明/探针/结论 | 跨上游的模型一致性,挂在平台段末或全局,待定 |

## 二、横切规则(不变)

新鲜度铁律 §9.1;写操作只走 Action;金额整数最小单位+币种、未知币种 fail closed;
凭据永不明文;Fake 来源全局横幅;逐页 RequireScope、403 提示缺哪个 scope。
